# Missing sales stock row correction

Replace your existing WinImportData form code with the complete WinImportData.vb (WinImportData.txt contains identical code). Retain the existing Designer and resources. No change to Import.vb is required. Do not add the helper/check files separately to your project; the helper is already embedded in the complete form.

The supplied negative-stock fallback resolves products without Mas_Stock, but Add_Sales updates existing stock rows only for normal sales. Missing rows therefore also miss the stock deduction. The correction seeds missing normal sales and nonzero free-quantity stock keys at zero quantity before Add_Sales, using GDCode + SysProdCode + Batch + MRP and the final fixed-width procedure parameters. Add_Sales performs its original deductions. Existing rows, rates and quantities are not overwritten. Seeding runs only when the negative-stock setting is enabled. Return lines are skipped. Purchase, calculations, grouping and IMEI code are unchanged.

The stock insert and Add_Sales run within one SQL transaction. A procedure error, nonzero return value or existing tracked-save verification failure rolls back the new rows and the sales save. IMEI processing still follows the successful sales save, as in the supplied code. This change does not make the pre-existing override deletion or separate IMEI transaction atomic with the sales save.

Installing the file affects subsequent saves/imports. It does not repair already imported bills. Existing affected invoices need a separately verified repair or the application's permitted override/re-import workflow; do not import them under new invoice numbers merely to fix visibility. No existing database records were modified in preparing this file.

Validation: the helper compiles with the installed .NET Framework VB compiler. Executable SQL tests on a temporary table using the local analysis database's Mas_Stock schema pass for missing and zero MRP, quoted batch, preserving existing negative quantities, separate godowns, free stock, return bypass, negative-setting bypass and rollback. Removing the helper, transaction-aware verification change and sales-save wrapper restores the supplied source exactly. The full ERP project and edit/print screens were not available to build or run. Confirm the replacement in your ERP test database with a new missing-MRP sale, then reopen and print that bill and check its stock quantity.
