# Purchase writer matrix — pre-edit review

All four routes retain ensureConnection, global authenticateApi and VOUCHERS/PURCHASE add/edit/delete grants. Global authentication rejects supplied tenant mismatches; the new guard also compares tenant to req.auth. All use manual startTransaction + commitTransactionReliably; callback retries are absent and will remain absent.

| Route | Authoritative dates to guard | Existing mutation order after reads | Session / decision |
|---|---|---|---|
| POST /api/purchase | proposed invoiceDate | counter, header, journal, audit, stock upserts, commit | Counter explicitly receives session; stock upserts, journal, audit and header share session. Guard before counter. No allocation writes. |
| PUT /api/purchase/:id | stored invoiceDate, proposed invoiceDate, latest eligible POSTED original journal.documentDate | reverse old stock, add new stock, header update, journal reversal at proposed invoiceDate, repost, audit, commit | Stored header and latest journal loaded with same session. Guard before stock. Existing backward-reversal restriction remains. No number allocation. |
| DELETE /api/purchase/:id | stored invoiceDate, current businessDateIST cancellation/movement date, latest eligible original journal.documentDate | stock decrements, header cancellation, journal reversal, stock movement records, audit, commit | All mutations share session, including chained Stock.updateOne.session. Capture current date once for guard/reversal/movement consistency. Repeated cancellation returns 404. |
| POST /api/purchase/reconcile-desktop-import | stored invoiceDate; stored-or-request fallback posting/movement date for reactivation | stock add/reactivation or rates/isActive update, items replacement, optional reactivation journal and movement, save, audit | Existing transaction sufficient. Guard before stock loop. Missing stored date fails closed. Reactivation posts historically using stored date; preserve this behavior without certifying A1 policy correctness. Active repair does not create a missing journal. |

Latest eligible original selection must match reverseSourceJournal: tenant + PURCHASE + sourceId, descending postingVersion; include date only if POSTED and not reversalOf. Do not select an earlier original when latest event is a reversal. Repair does not reverse an original journal and does not need a reversal-date check. Purchase stock helper and resolveStockRowContext pass session through existing reads/upserts; no inventory costing or batch policy change required. Product tax helper performs same-session reads and changes request items only. Journal services preserve lines, reversalOf, status, versions, existing no-op rules. Audit uses the caller session. Financial-period guard writes only the tenant control revision inside the same transaction.

Number index prevents duplicate purchase numbers including cancelled rows; create has no idempotency-key result lookup. Repair retries keep missing-row-only quantity behavior, cancelled reactivation adds quantity once after successful reactivation; active repair still updates rates/metadata/audit on repeat. Preserve these contracts. commitTransactionReliably retries only unknown commit results, not whole callbacks. No production access or transaction architecture change is needed.

Policy caveats: edit reversal/repost at proposed invoiceDate and repair reactivation at historical invoiceDate remain existing behavior, not an A1 date-policy correction. Any migration to explicit adjustment dates or different original treatment requires a separate decision. No such correction is implemented.
