## Remaining dependencies

The complete verified inventory must follow indirect helpers, dynamic registrations, import mappings and all mutation branches, including early returns and legacy duplicates. Static absence of a guard token is evidence of missing direct integration, not proof about every indirect call. Existing test names do not certify a route. A complete acceptance matrix must identify each covered route and assert denial before every dependent mutation with the same session.

Source-date checks for edits/cancellation, reference-date policy for allocations, future-date policy, and opening corrections remain unresolved where they require business-rule changes. Current reversal-date arguments remain untouched. Existing opening supersession is not an immutable opposite-event correction; period integration must not claim to fix that historical issue.

Approval of staged implementation does not certify these dependencies resolved. Stop each affected portion if a new transaction architecture, document-date rule or historical data change becomes necessary.
